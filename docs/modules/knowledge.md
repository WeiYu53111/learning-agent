# 教材知识模块详细设计

## 1. 边界与接口

输入为本地 PDF 和提取配置，输出可版本化的教材结构、目标、依赖及原文证据。不查询用户掌握情况，不根据用户水平改变教材提取内容。

```text
parse_document(path, limits) -> ParsedDocument
build_draft(document_id, extraction_profile) -> KnowledgeDraft
validate_draft(version_id) -> QualityReport
publish(version_id, expected_revision) -> PublishedVersion
get_outline(version_id) -> SectionTree
resolve_scope(version_id, section_id | point_id) -> ObjectiveScope
get_dependency_graph(version_id, objective_ids) -> DependencyGraph
select_evidence(version_id, objective_id, purpose, token_budget) -> EvidenceBundle
```

ParsedDocument 包含逐页原文、规范文本、标题候选及不可用页清单。QualityReport 区分硬错误、人工警告、覆盖缺口和可发布范围。EvidenceBundle 包含片段、SourceRef、物理页码及覆盖的 rubric 要点。

## 2. 文件与解析

默认限制：文件 20 MiB、2000 页；限制可配置，超限在模型调用前拒绝。检查存在、普通文件、扩展名和 PDF 文件头，解析库能读取才算有效；不能只凭扩展名接受。

保留原始 PDF，逐页提取文本和版式信息。规范化仅统一换行、去除无效控制字符，保留字符映射；不能为美化文本改变引用位置。无文本页与疑似扫描页单独标记。文字数量阈值是检测信号，不能把短教材直接判为扫描件。

书签目录优先，正文标题定位辅助确认。没有书签时按编号、字号和字体提出章节候选，过滤目录页和重复页眉。章节边界保存 `(physical_page, char_offset)`，页码范围仅供展示；同页多个标题不能共享整页正文导致重复归属。

父章节展示范围可以包含子章节，提取以叶级正文及父级直属文本为单元，每个原文范围只处理一次。没有可靠目录则建立“全文”章节，报告较低结构置信度，仍允许后续人工确认。

## 3. 原文切片与定位

以段落为基础建立单页片段，默认目标 800–1600 字符，长段按句界拆分，必要时最多 200 字符重叠。字符数只用于预切片，真实请求前由网关检查 token 预算。

每个 chunk 保存 page_id、page_start/page_end、normalized_text、text_hash。SourceRef 指向 chunk 内的区间；显示时通过 chunk 与页面映射回物理页。原始提取文本和规范文本都保存，引用校验使用后者。

重叠区产生的知识候选按原文范围和语义合并，不能把重复片段误当两条独立依据。跨页论述使用多个 SourceRef，不伪造一个跨页 chunk。

## 4. 分批提取与目标建模

每批输入章节标题、原文片段与已提取候选摘要，模型输出临时 point_key/objective_key、名称、描述、维度、评分要点、依赖候选和精确 SourceRef。

同步提取有教材依据的误解定义候选及关联目标，发布时形成版本内受控 code 目录，记录哪些关联目标属于 critical。题目生成只使用该目录；作答中新出现的自由文本误解先隔离为候选，不修改已发布目录或直接阻塞达标。

目标必须用“解释、区分、分析、完成”等可观察行为描述。每目标指定 required、关键要点和可评估题型。概念、原理和应用是否必需取决于教材目标，不机械地给每个术语添加迁移题。

先在批内解析 key，再跨批去重和解析依赖。每个候选保留生成来源。文本相似只用于提示可能重复，不能直接合并语义不同的目标；存在冲突时进入人工警告，不静默丢弃。

程序分配正式 ID。候选对已有身份的映射仅在内容等价或人工确认时保留；语义变化创建内容版本；拆分/合并创建显式 mapping，旧目标仍保留。

必要依赖是目标级有向边：source 为前置，target 为后续。supporting 只辅助讲解，不参与阻塞。模型提出的教材外必要依赖标记 unresolved；不得自动编造一个无来源目标以通过校验。

## 5. 质量与发布

硬校验：引用范围及 quote 一致、目标可定位、rubric 非空、所有必要边端点存在、必要依赖无环、至少一个可教学目标。只有语法正确的模型输出不能直接发布。

人工警告：目标粒度、覆盖缺口、疑似重复、章节低置信度、公式或图表依赖。CLI 逐项展示，用户可排除目标或章节；排除后重新检查依赖闭包，不能发布依赖被排除目标的内容。

第一版用 inspect 查看质量报告，用交互发布流程确认、排除候选及重新提取有问题的批次，不要求用户手工编写数据库记录。人工修改同样产生草稿修订，发布前重新校验。

部分教材可发布明确的子范围：excluded 范围、缺口及理由随版本保存，教学入口只接受 included 范围。硬错误不能通过确认绕过。

## 6. 证据选择与缓存

证据选择先取当前目标直接引用，再按缺失 rubric 要点补充同章节片段，最后取已确认必要前置的相关定义。按要点覆盖、直接引用优先、原文顺序稳定排序；不将完整历史对话混入教材证据。

预算不足先移除低相关辅助片段，不能删掉关键依据继续生成。仍不足则拆成较小教学任务，或返回 KNOWLEDGE_UNAVAILABLE，说明哪个要点缺证据。保留每次 EvidenceBundle 的 ID 和内容哈希供追溯。

文档去重按文件哈希；解析缓存按哈希和 parser_version；提取缓存按解析版本、模型、提示词、契约和提取参数规范哈希。用户水平、目标和学习记录不在缓存键中。

重提取生成新草稿，发布是独立操作；已发布版本不可变。重复导入复用已有可用版本，`--reextract` 显式生成草稿。失败批次记录状态，恢复只重跑未成功批次。

## 7. 测试

使用自建 PDF 覆盖中文、书签、同页多标题、无目录、空白页、混合扫描、页眉、重复段落和超长章节。以固定候选测试依赖环、悬空边、精确引用、部分发布、去重与版本隔离。人工审查目标粒度及原文支持度，不把规则校验宣称为语义正确性证明。
