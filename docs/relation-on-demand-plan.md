# 候选对检查点与按章关系分析实施计划

日期：2026-10-26  
状态：待实施。本文描述下一阶段方案，不代表下列新增命令、参数或表结构已经可用。  
范围：候选对级恢复、内容就绪与关系就绪分离、按章补充先修关系；不同时调整模型、并发和检索算法。

## 1. 问题与目标

当前实现已用本地词项检索替代摘要组的全量两两分析，按 `relations_v2:plan` 固定批次计划并保存每批结果。但仍有两个限制：

1. 完成状态属于批次，调整候选策略或批次大小后，不能直接按新的计划复用每一对的判断。
2. `index` 在全书关系分析结束后才设置 `ready`；`learn` 必须等待这个状态，即使用户只需要学习某一章。

本次目标：

- 模型仍按批调用，持久化进度改为按候选对记录；改变批次大小不重做已检查的配对。
- 全书提取、覆盖校验及章节摘要完成后即可进入按章学习入口。
- 选择章节时，只分析该章及必要前置的候选关系；用调用预算和展开深度控制范围。
- 明确区分“未检查”“已检查但未建立关系”“已检查且有关系”。
- 保留已保存结果、旧教学版本及旧会话，恢复不重复消耗模型请求。

不承诺穷尽真实知识关系；“候选已检查完”只指特定候选策略及知识内容版本下的覆盖情况。

## 2. 两项改动如何配合

例如候选对 A-B、A-C、B-C 一起提交给模型。成功校验后分别保存：

| 配对 | 状态 | 结果 |
| --- | --- | --- |
| A-B | checked | A 是 B 的前置 |
| A-C | checked | 当前依据不足以建立关系 |
| B-C | checked | 相关 |
| A-D | pending | 尚未检查 |

以后只将 pending 的配对重新分批。用户学到包含 D 的章节时才处理 A-D；若 A-B 已被其他章节分析过则直接复用。无关系记录不是“证明没有关系”，只是本次检查未建立关系。

内容变化时重新计算内容指纹：修改 B 只使涉及 B 的旧判断不能用于新内容；A-C 保持有效。旧判断保留供历史版本追溯，不原地覆盖。

## 3. 状态拆分与启用规则

### 3.1 内容状态

增加独立的内容就绪状态，不能继续用一个 `ready` 同时代表内容完整和关系完整。

| 状态 | 条件 | 能否创建新的章节教学任务 |
| --- | --- | --- |
| building | 提取、章节摘要或内容校验尚未完成 | 否；允许原文问答 |
| ready | 全书提取、章节摘要、引用与覆盖校验已完成，内容快照已保存 | 可以进入按章关系检查 |

关系检查失败不撤销内容就绪状态。缺少可读取原文的页面仍明确列出，不当作已理解内容。

首次发布内容快照须在同一事务中写入 points、items、summaries、unavailable_pages 及内容就绪状态。保存之前崩溃，继续复用提取和摘要检查点重建快照。

### 3.2 关系覆盖状态

按全书或章节任务分别记录 `not_started / partial / candidate_complete`；错误作为任务的最近失败信息保留，不能把失败批次计入已完成。

覆盖统计至少包含候选总数、已检查数、有关系数、无关系数，以及因深度限制而未展开的前置节点数。计数由当前策略下的任务成员和有效检查结果计算，不能用已返回边数推算完成度。

某一章所有直接候选检查结束，不代表其前置链也已检查结束。存在未展开的前置节点时，章节任务仍为 partial。

### 3.3 版本选择

- 新任务选取最新的内容就绪索引。较新的 building 索引不挤掉旧的可用内容版本。
- 新内容版本可复用指纹相同的配对判断；必须在新版本关系图中重新执行全局环路校验。
- 已有教学任务、已发布版本和会话沿用原绑定，不随新的内容或关系状态静默变化。
- `active()` 的调用方逐一审查，新增明确的内容版本选择接口；不得直接把所有原 `ready` 判断放宽。

## 4. 持久化设计

在现有 schema 5 基础上实施增量迁移，建议使用 schema 6。下面是逻辑字段，实施时补齐外键、唯一约束和查询索引。

| 数据对象 | 主要字段与用途 |
| --- | --- |
| index_content_state | index_id、status、content_fingerprint；独立表达内容是否可用 |
| relation_checks | book_id、规范化 pair_key、两端知识点 key 和内容指纹、validator_version、result、origin、model、created_at；不可变的有效判断缓存 |
| relation_tasks | id、index_id、scope（全书/章节）、section_id、selector_version、validator_version、status、frontier、展开深度、最近失败信息 |
| relation_task_pairs | task_id、pair_key、两端指纹、引入原因、匹配的 check_id；任务成员唯一，支持统计和恢复 |
| relation_requests | id、task_id、候选成员及其指纹、请求参数摘要、状态、失败候选、错误、耗时；用于批次原子提交和审计 |
| relation_graph_edges | index_id、check_id、source、target、kind、reason、graph_revision；保存该索引接受的关系图 |
| lesson_relation_snapshots | version_id、index_id、graph_revision、教学所用关系与前置上下文、覆盖状态、任务及策略版本、用户是否接受部分覆盖 |

设计要求：

- pair_key 按两个知识点稳定 key 排序生成，候选本身无方向；result 中的 prerequisite 保留明确方向。
- 指纹涵盖标题、描述、原文引用及所属章节；不得只凭知识点 key 判断缓存有效。
- selector_version 决定“挑哪些对”，validator_version 决定“怎样解释和验证结果”。改变批次上限不改变这两个版本。
- 选择策略变化时重建任务候选，但复用兼容的判断；校验契约或语义变化时显式更换 validator_version。
- 模型信息记录来源；默认切换模型不清空已完成结果，与当前恢复行为一致。主动重评通过新 validator_version 或后续独立功能实现，本期不隐式重评。
- 未检查配对仅存在于任务成员中；只有成功完成的判断才写入 relation_checks。失败不可写成空关系。
- 缓存判断和索引接受的边分离：某个旧判断在新图中引发环路时，不覆盖缓存、不污染图，作为冲突候选重新校正。
- 不以可变的 book_indexes.data.relations 作为旧教学版本的唯一关系来源。

## 5. 模型契约与批次事务

### 5.1 显式逐对作答

新契约要求每个请求候选恰好返回一个判断，示意：

```json
{
  "checks": [
    {"pair_id": "pair_ab", "relations": [
      {"source": "A", "target": "B", "kind": "prerequisite", "reason": "依据说明"}
    ]},
    {"pair_id": "pair_ac", "relations": []}
  ]
}
```

空 relations 表示已检查但依据不足。禁止遗漏、重复或额外 pair_id；关系端点必须属于该候选对。旧契约仅返回关系列表，不能直接作为新契约成功响应解析。

### 5.2 调用和恢复流程

1. 在单写者锁内读取任务未检查成员，按当前字符和配对数量预算组批；保存请求成员快照后提交短事务。
2. 事务外调用模型，不在网络等待期间持有数据库事务；数据目录单写者锁仍遵循现有策略。
3. 校验完整性、候选范围、自关联、关系类型和合并后的全局前置环。
4. 一次成功事务写入本批全部检查结果、接受的边、任务成员关联、图修订号和请求成功状态。
5. 失败保存候选和原因，最多自动校正一次；仍失败暂停。整批校验未通过时，不将其中任一候选标记为已检查。
6. 中断后重组尚未检查的配对。请求结果已成功提交的配对不会再发送；已发出但未提交结果的请求可能重发，不承诺外部调用严格恰好一次。

批次只是运输单位，数字编号不再决定缓存身份。调整 32/64 对上限或字符预算后，重启即可对剩余成员重新分批；不得删除已完成配对。

本期保持整批校验与原子提交，暂不实现坏配对局部修复，避免混入额外复杂度。

## 6. 按章先修关系分析

### 6.1 初始候选

用户选择 s5 后：

1. 确认全书内容已就绪，并固定 index_id、selector_version 和 validator_version。
2. 使用现有确定性候选生成器生成候选；取至少一个端点属于 s5 的所有候选，包括由其他章节知识点选中 s5 的反向候选。
3. 复用有效检查结果，将未检查配对加入任务；本期可在本地计算全书候选，局部化的是模型请求范围。
4. 初始候选允许分析同章关系以及候选中的跨章关系。词项相似度只决定候选，不能直接生成前置边。

### 6.2 前置展开

- 从 s5 的知识点出发，仅沿已接受的 prerequisite 反向追溯；related 不扩展学习范围。
- 新发现外章前置 B 时，加入至少一端为 B 的候选；不因此分析 B 所属整章的所有知识点。
- 使用 visited 集合去重，按稳定顺序处理待展开队列，保存 frontier 以便恢复。
- 已自报掌握或已验证掌握不改变关系事实，也不用于宣称关系已完整；掌握状态只影响后续补学提示。
- 默认一次 learn 最多 4 次模型调用，最多展开 2 层外章前置。自动校正同样占调用预算；候选与判断缓存命中不占预算。
- 这两个值是首版可配置默认值，不是质量保证；可通过显式关系命令增加调用预算或深度。
- 每次调用前检查预算。到达调用预算时保留剩余成员；到达深度限制时保留未展开节点，不将其当作已查明的链尾。
- 没有 pending 配对且没有未展开 frontier 时，才将当前任务标记为 candidate_complete。

增加深度时继续展开原 frontier；增加调用预算时只处理剩余候选。重复命令不会仅因调用次数上限而删除任务或清零进度。

### 6.3 未完整时如何学习

预算耗尽或分析失败后保留内容和关系进度。交互终端展示已检查数量、尚未展开节点及失败原因，提供“继续分析／按当前已知关系学习／退出”。

非交互执行默认暂停，不生成新的教学版本；只有显式传入 `--allow-partial-relations` 才允许使用部分关系继续。此选择和覆盖信息写入教学快照，不能转成自报掌握。

已发现的必要前置继续沿用现有“补学／我已掌握／本次跳过”选择。接受部分覆盖不等于跳过已经发现的前置知识，两者分别记录。

## 7. 命令行为（拟新增）

为避免现有脚本语义突变，保留 `index BOOK` 的全书分析目标，新增只整理内容的入口。

| 命令 | 预期行为 |
| --- | --- |
| `teach index BOOK` | 提取、摘要后保存内容就绪快照，再继续全书候选关系分析；可恢复 |
| `teach index BOOK --content-only` | 到内容就绪即结束；已有内容时复用，不删除已有关系或任务 |
| `teach relations BOOK` | 要求内容就绪；显式补齐全书当前策略的候选关系 |
| `teach relations BOOK --section s5` | 创建或恢复 s5 的局部关系任务；默认 4 次调用、2 层展开 |
| `teach relations BOOK --section s5 --max-calls 8 --max-depth 3` | 在同一任务上增加本轮调用预算和展开范围 |
| `teach learn BOOK --section s5` | 优先恢复已有教学/会话；创建新教学任务时执行局部关系检查，然后沿用现有教学准备流程 |
| `teach learn BOOK --section s5 --allow-partial-relations` | 接受局部分析仍不完整，并按已知关系准备教学；记录该选择 |
| `teach outline BOOK` | 只读展示内容状态、全书候选覆盖及各章已存在任务状态，不启动分析 |

`--max-calls` 可用于全书 relations 命令限制本轮请求数；不传时显式全书命令处理至当前候选完成。章节命令预算耗尽并有未处理内容时返回可区分的暂停退出码，建议 3；失败沿用错误退出码。明确接受部分覆盖并成功准备教学可返回成功。

`index --new` 仍管理新知识结构版本，不用作关系任务重试开关。存在未完成的新索引时沿用现有优先恢复行为，并明确显示恢复的 index_id。

用户推荐路径：

```bash
teach index BOOK --content-only
teach learn BOOK --section s5
# 需要全书关系时再显式执行：
teach relations BOOK
```

内容整理尚未结束时，learn 提示先恢复 index，不隐式发起全书提取。普通 index 在关系阶段暂停后，内容已可用于后续 learn；不能同时启动两个写进程。

## 8. 教学版本绑定与旧会话稳定性

在关系范围确定、用户接受覆盖状态之后，创建教学版本及 lesson_relation_snapshots，并在同一事务中绑定。快照至少包含本次教学实际使用的前置上下文和关系、候选覆盖及图修订号。

`build_lesson`、`prepare`、前置提示及同章目标依赖映射统一读取该快照。之后全书关系增加，不改变已生成目标、审核结果、评分依据或现有会话的补学提示。

重复 learn 优先恢复现有教学版本，不先执行新的关系分析。用户选择 `learn --new` 时，才使用当前内容及新的关系快照准备新教学版本。

历史教学版本没有快照时，迁移时从原绑定索引提取可用关系并标记 legacy 来源；没有可靠覆盖信息时显示“历史覆盖未知”，不得伪造为完整。

## 9. 旧数据迁移和恢复

### 9.1 数据库迁移

- 迁移须持有现有单写者锁；新增表和迁移标记在事务中提交，重复运行无重复记录。
- 保留所有原 book_steps、book_indexes、lesson_links、教学及会话数据；不要求用户重导入教材。
- 原 ready 索引标记内容就绪；原 building 索引在下一次 index/learn 准备阶段复用提取和摘要，校验并保存内容快照，不能只凭记录数量判断完成。
- 原 ready 的全书覆盖仅能声明为“旧策略已完成”；不能自动宣称新策略或新验证契约已完成。
- 不支持迁移后直接用旧代码写新库；回退代码须恢复实施前备份，不降级删除新表或修改 user_version 冒充旧库。

### 9.2 当前 relations_v2 检查点

- 从保存的 plan 中逐批读取 candidate_pairs；只有存在成功 batch 结果的批次可以迁移。
- 对照成功响应校验端点及关系图，再将该批所有候选分别标为已检查；未返回边的候选标记“旧契约下未建立关系”。
- 保留 `legacy_implicit` 来源，明确旧契约依靠成功响应的省略表达无关系；新契约必须逐对显式回答。
- 没有成功结果、只有 rejected 或请求中断的批次，不迁移任何已完成标记。
- 检查点与计划不一致时暂停并报告具体记录，不猜测候选成员。

### 9.3 更早的 relations:i:j 检查点

- 按原算法重建 6,000 字符摘要组，并验证知识点及分组一致性。
- 保存成功批次中的所有有效正向关系；对于当前候选集合，成功分析过相应分组组合的配对可按旧语义复用。
- 同样使用 legacy_implicit 来源，不把组内全部知识点组合展开成巨大的负结果表。
- 旧覆盖证据保留为紧凑的分组记录；后续新增候选可按需查询旧覆盖，再物化具体配对判断。
- 无法可靠重建分组时保留可校验的正向边，但不推断负结果覆盖；日志说明需要重查的范围。

迁移采用独立算法版本及完成标记；中断后幂等恢复。任何缓存导入都必须经过对应索引的全局图校验。

## 10. 日志和可观测性

日志分别输出内容进度、候选覆盖和当前请求，不再用一个批次数暗示全书语义完成度，例如：

```text
内容整理完成：996 个知识点，可选择章节学习。
s5 关系检查：候选 120 对，已检查 80 对；本轮最多 4 次模型调用。
本轮第 2/4 次调用：32 对候选，等待模型处理。
s5 已检查 112/120 对；另有 3 个前置节点因深度限制尚未展开。
关系分析尚未完整，可继续分析或按当前已知关系学习。
```

计数以上述事务提交后的状态为准。记录请求输入 UTF-8 字节数、输出字节数、耗时、重试数和复用配对数，明确这是业务载荷统计，不是实际网络流量或 token 用量。

## 11. 实施拆分

| 阶段 | 工作内容 | 交付条件 |
| --- | --- | --- |
| A | 新增数据表、逐对响应契约、配对缓存、全局图校验、旧检查点迁移 | 原 index 流程可运行，调整批次大小只处理剩余配对 |
| B | 内容状态独立、内容快照、`index --content-only`、outline 状态 | 关系失败不影响内容就绪；旧版本选择和只读命令保持正确 |
| C | 章节候选任务、前置队列、调用/深度预算、relations 命令 | 局部分析可暂停恢复，不误计未展开节点为完成 |
| D | learn 接入、部分覆盖交互、教学关系快照、旧会话兼容 | 新任务按需分析，旧任务不因关系更新而改变 |
| E | 文档、离线端到端测试、代表性真实模型对照 | 验证请求节省及语义风险，报告测量范围 |

每阶段单独可审查、可测试。先保持当前 32 对/约 12,000 字符的批次设置，批次大小实验作为独立后续优化，不把收益混入本次结果。

## 12. 验收标准

### 恢复与数据安全

- 一批包含有关系和空关系两种结果时，全部成功后可逐对复用。
- 响应遗漏、重复、越界、自关联或形成跨批前置环时，整批不计完成；最多校正一次。
- 网络失败、Ctrl+C、结果提交前崩溃及提交后崩溃均可恢复；已提交配对不重发。
- 将批次上限从 32 改到 64，仅重新分组未完成配对；修改一个知识点只使相关旧指纹判断失效。
- 新图与缓存边冲突时不修改旧缓存和旧版本，不接受带环图。
- 旧正向结果、旧空结果、只有 rejected 的批次和损坏计划分别有迁移用例；迁移重复执行一致。

### 局部学习行为

- 内容就绪、全书关系未完成时可进入 learn 的局部分析阶段。
- 选择 s5 不向模型发送仅涉及无关章节的配对；候选包含其他知识点选中 s5 的情况。
- 前置链 A→B→C 正确沿前置方向扩展，related 不展开；环路不会导致无限任务。
- 调用预算包含校正请求；深度和调用预算耗尽后留下准确 frontier，重启可继续。
- 非交互默认暂停；显式接受部分覆盖后记录选择，但不伪造掌握或完整性。
- 局部任务统计与全书候选覆盖独立；“没有返回关系”与“未分析”显示不同。

### 教学与兼容

- 已有 draft/prepare/start/resume 和学习会话继续沿用原关系快照。
- 新关系加入后，旧题目、评分和自报掌握不变；新教学版本可使用新快照。
- 旧索引在新内容构建失败时仍可用；新内容可用后不能错误切换旧会话绑定。
- `ask`、outline、books 等只读或问答路径不自动触发关系分析。
- 删除教材级联处理新增表，不留下外键残留；导出/诊断路径审查新增状态。

### 质量与性能

自动测试使用离线/模拟后端，不把结构正确当成关系语义正确。真实模型对照另行显式运行，至少选取无跨章前置、多个前置和长前置链三类章节，记录：

- 开始章节教学前的模型请求数、总等待时间、业务载荷字节数和重试数。
- 与全书候选检查相比，已知必要前置的发现情况及漏检样例。
- 用户接受部分覆盖的次数、原因和后续补充关系的影响。
- 缓存命中率，以及改变分批参数后的重复调用情况。

本次没有真实模型对照数据，不预设固定加速比例，也不以单纯减少请求数作为质量验收通过条件。

## 13. 风险与实施边界

- 逐对显式响应增加少量输出，但消除了新请求“遗漏还是无关系”的歧义。
- 词项检索会漏掉同义和隐含关系；本期不加入向量数据库，不宣称关系完备。
- 全局环路检查保证结构约束，不证明模型判断语义正确。
- 前置展开可能触及很多章节，必须同时实施调用预算、深度限制和准确的未完成提示。
- 图修订与教学快照是按需分析的必要前提，不能只放宽 learn 的 ready 判断后发布。
- 单写者锁和串行模型调用保持现状；后台自动补齐、并发、自动重评和批次局部修复均不在本期范围。
