# 领域模型与教学状态机

> 2026-10-22 版本说明：本文下方的数值评分、失败清零与原作答状态机描述保留为 v1 设计记录。新作答已使用 v2 核心要求判断、失败减一次、定向缺口解除和最多两轮追问；旧作答及其复核沿用 v1。当前实现与边界以[评分进度记录](grading-issues.md)为准。

文档性质：保留第一版领域目标设计及旧规则，不表示全文仍待实现。当前实现范围见[原型说明](prototype.md)，新版评分规则见上方说明，未来工作见[计划总览](plans/README.md)。下列历史数值为工程规则，不代表经过校准的能力概率。

## 1. 领域契约

| 对象 | 关键内容 |
|---|---|
| Document / KnowledgeVersion | 文件哈希、存储位置、解析与模型版本、草稿/发布状态、覆盖范围 |
| Section / SourceChunk | 层级、顺序、页码、逐页文本范围、正文与可用性 |
| KnowledgePoint | 稳定 ID、内容版本、所属章节、名称、边界、质量状态 |
| LearningObjective | 独立 ID、知识点版本、可观察描述、dimension、达标要点、required、原文引用 |
| Prerequisite | 前置目标、后续目标、required/supporting、依据和确认状态 |
| Question | ID、主目标、题型、难度、题干、答案、rubric、来源、新颖性分组 |
| Attempt | ID、题目、会话、原始回答、时间、提示和答案展示事件 |
| Assessment | 作答 ID、修订号、有效性、分数、回答证据、覆盖/缺失要点、误解与版本 |
| ObjectiveMastery | 用户、目标版本、估计值、证据数、独立通过次数、状态、最近验证、规则版本 |
| Misconception | 规范误解码、相关目标、支持/反驳证据、生命周期 |
| Session | 用户、知识版本、目标范围、当前阶段、生命周期、修订号、暂停原因 |
| TeachingDecision / SessionEvent | 动作、理由、依据、策略版本、操作 ID、递增事件序号 |
| ReviewItem | 用户、目标版本、到期时间、复习阶段、关联复测证据 |

维度统一为 `concept/reasoning/application/transfer`；目标 ID 不能用维度名代替。一个目标对应一个主维度，一个知识点可以有多个同维度目标。

第一版一道题只更新一个主目标。综合题可以关联其他目标，但不能把总分复制到所有目标。无有效证据时估计为 null。所有引用必须存在且属于合法知识版本。

模型输出采用严格 Pydantic 契约。未知动作、越界分数、错误目标和引用必须拒绝，不静默修正。生成的题目、rubric 和教学内容保存后固定，恢复不临时改写。

## 2. 评估有效性与修订

- `valid`：依据和结论一致，可以更新掌握。
- `needs_review`：含糊、矛盾或依据不足，保存回答但不更新掌握。

评分依据学习者实际表达的语义证据，不逐句匹配参考答案。未明确考查严格 JSON 或可执行代码时，完整且无歧义的字段、类型和值表达应接受，不因缺少外围大括号或键名引号扣分；已表达的事实不要求重复术语或复述题干前提。题目明确要求的核心推理仍须有回答证据，不能凭题干替学习者补全。出题时所有计分要求须明确体现在题干中，关键项不得捆绑多个独立补充要求；旧题若存在影响公平评分的题干与 rubric 冲突，返回 invalid_question 并指出冲突，不降低权重或强行给满分。

上下文指代属于回答语义的一部分：若题干明确对象来源，学习者用唯一指向该对象的简称主动完成正确的概念对应，不要求再重复来源主语。评分引用仍须来自学习者原句，理由中解释指代关系；不能伪造题干文字为回答证据。仅有题干信息、没有学习者的对应判断，或需要的额外推理并未表达时，不可据此给分。出题也应避免先给出来源，再将复述来源作为额外扣分项。
- `invalid_question`：题意歧义、条件不足、参考答案错误，本次不计分。

规则层检查目标与评分要点对应、引用有效、证据摘录来自回答、得分与通过结论一致。模型逐 rubric 项给出 0/0.5/1 的覆盖程度，程序按固定权重计算分数，不直接接受模型总分。分数 ≥ 0.8 且全部关键要点完全覆盖才算通过。有效评分即使总分达到 0.8，只要关键要点未完全覆盖，仍为有效的未通过证据，正常进入掌握投影；程序不得因此将其改成 needs_review。模型明确返回的 needs_review 仍不计入掌握。模型自评置信度仅为辅助信号。

待复核最多再做一次独立复核，仍不确定则换新题。独立复核与初次评分共享同一模型请求预算；预算不足时保留回答、暂停评分，待用户明确重试。无效题记录原因后替换，不扣掌握。

原始作答不可覆盖。改分创建新的评估修订，记录替代关系和原因。每条作答只取当前有效修订，按时间顺序重算受影响目标及复习安排；有效修订切换和投影更新在一个事务内完成。保存模型、提示词、题目、rubric、契约和规则版本。

提示使用由实际展示事件推导，不依赖用户自行申报。已展示答案的题标记暴露。

## 3. 掌握与误解规则

目标状态：`unknown/learning/needs_remediation/provisionally_mastered/review_due`。

1. 无有效评估：unknown，估计为 null。
2. 有效评估得分 s：无提示且未暴露答案使用 s；用提示使用 0.7 × s，不算独立通过。
3. 已看答案或重复相同题目的回答仅保存练习证据，不增加估计或独立通过次数。
4. 首条可计分证据直接设为调整后得分，后续为 `0.6 × 旧估计 + 0.4 × 本次调整后得分`。该平滑估计仅用于展示趋势，不参与达标、推进或复习通过判断。
5. 最近独立评估失败或存在已确认的关键误解时为 needs_remediation。
6. 自最近一次独立失败后，至少两道不同新颖性分组的新题独立通过，且无未解决关键误解，才初步掌握。单题通过仍要求分数 ≥ 0.8 且全部关键要点完全覆盖；新的独立失败会清空本轮通过组计数。
7. 其他有证据状态为 learning；辅助通过不能清除补救需求，须新题独立验证。

示例：首次独立满分估计 1.0，仍为 learning；第二道不同场景题独立满分后才初步掌握。提示后满分估计 0.7，独立通过次数为零。

边界示例：首次独立得 0，随后两道不同场景题均独立得 0.8 且覆盖全部关键要点，趋势估计为 0 → 0.32 → 0.512，状态为 needs_remediation → learning → provisionally_mastered。达标依据近期独立证据，不能因为历史低分继续无限出题。

知识点达标要求全部 required 目标达标，不用均分掩盖应用缺口。进度分别展示覆盖、达标、跳过和待验证。

误解状态：suspected → confirmed → resolved。一次错误只形成候选；两个不同场景的有效证据支持后确认；两个针对该误解的新场景独立验证通过后解除。再次出现可重新打开，保留历史。

题目通过 `targeted_misconception_codes` 指明要验证的受控误解码；评估通过 `misconception_results` 返回逐码的 supports/refutes/inconclusive、rubric 项和回答证据。只有题目明确针对该码、评估为 refutes 且整题独立通过，才计入解除证据。普通通过、遗漏误解字段或非独立回答不能解除误解。

## 4. 状态与动作

生命周期：`active/paused/completed/ended_with_gaps`。active 内阶段：`planning/awaiting_answer/evaluating/feedback_ready`。流程状态与掌握状态独立。

教学动作统一为 `DIAGNOSE/EXPLAIN/EXAMPLE/PRACTICE/HINT/REMEDIATE/REASSESS/ADVANCE/REVIEW/SUMMARIZE`。等待、评估属于运行阶段。

| 条件或事件 | 处理 | 下一阶段 |
|---|---|---|
| 开始或切换目标 | 查历史及依赖，未知则诊断 | awaiting_answer |
| 有充分且未过期证据 | ADVANCE 并记录理由 | planning |
| 提交回答 | 保存操作 ID 和原始作答，评估 | evaluating |
| 有效通过 | 更新目标，给出反馈 | feedback_ready |
| 首次通过但独立证据不足 | 用户确认后以另一新颖性分组的新题 REASSESS | awaiting_answer |
| 有效失败 | 定位错误，讲解、示例或补救，再用新题验证 | feedback_ready |
| 待复核/无效题 | 不改变掌握，复核或换题 | feedback_ready |
| 请求提示 | 展示并记录，保持当前题 | awaiting_answer |
| 请求讲解 | 标记可能的答案暴露，后续换题 | feedback_ready |
| 跳过目标 | 标记 skipped，检查依赖阻塞 | planning |
| 暂停/退出 | 保存检查点 | paused |
| 全部必需目标达标 | 总结 | completed |
| 所有目标处理完但仍有缺口 | 列出跳过、阻塞和未达标目标 | ended_with_gaps |

反馈展示后等用户确认继续，再生成下一任务。planning 是应用内部阶段：ADVANCE、目标选择及总结判断自动执行，直到 awaiting_answer、feedback_ready、paused 或终态，CLI 不需要额外输入解锁 planning。每次内部循环上限为 `2 × 本会话目标数 + 8`，同一状态无进展或超限则暂停并报告策略错误。每会话最多一道活动题；只有当前题提交、跳过或撤销后才创建新题。已完成会话可查看；需要复测时新开复习会话。

## 5. 规划与补救预算

章节入口对 required 目标及必要依赖做拓扑排序；知识点入口构建局部目标和前置闭包。辅助知识不阻塞。未知前置先诊断，过期关键前置先复测。依赖环、悬空依赖和教材外必要依赖必须在发布前处理，证据不足时告知缺口并允许缩小目标。

只安排当前任务和少量候选，依据新证据重新决策。补前置时保存返回目标，通过后返回原目标。用户自述已懂仅改变诊断起点，不直接更新掌握。

初始停止预算：每目标每会话最多 8 次已提交作答、3 次有效失败、2 次无效题替换，连续 2 次待复核仍无法解决时暂停目标，前置展开最多 3 层。总作答数按不同 Attempt 计数，包含辅助、练习和隔离证据；重试及评分修订不增加次数。先处理最后一次提交的评估和达标结果，再检查是否允许出下一题，最后一次允许的作答可以正常达标。

未达标且达到任一预算时，将目标 deferred 并显示原因；允许仅换讲解、跳过或结束，本会话不再自动出评分题，不能自动清零形成循环。必要依赖更深时要求明确扩大目标范围。

失败后依次定位错误、换示例、检查前置，复测必须使用新题。跳过必要前置时后续目标 blocked；允许预览，但不宣称达标。直接请求讲解不改变未验证状态。

## 6. 复习

初步掌握后 1 天复习，后续独立通过后间隔为 3、7、14 天。到期进入 review_due，保留估计，不因时间直接扣分。

复习按必要前置优先、到期时间排序，使用新题。已有达标证据且复测通过时可推进间隔；失败进入补救，重新满足初步掌握条件后从 1 天开始。14 天为第一版最大间隔，此后重复该间隔。无效题和待复核结果不推进复习阶段。
