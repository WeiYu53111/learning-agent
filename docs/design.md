# CLI 教学 Agent 总体设计

状态：已提供 CLI 原型。本文保留完整目标设计，实际命令、已实现范围及取舍见[原型说明](prototype.md)，未实现契约不视为已经验收。

## 1. 目标与范围

以 PDF 为教材依据，以结构化学习者模型为长期记忆，通过诊断、讲解、练习、补救和复测持续调整教学。核心验收：同一目标下，已经掌握、只会定义、缺少前置知识的学习者获得不同且有依据的教学路径。

第一版：单用户、本地 CLI，同一数据目录只允许一个写进程，只读命令可同时查询已提交数据。允许导入多个文本型 PDF，每次会话绑定一本教材的一个知识版本；支持章节和知识点入口。不包含 Web、登录、OCR、图表理解、向量数据库、多 Agent 或模型训练。

扫描件、加密文件和无可用文本的 PDF 拒绝导入。部分页面无文本时标明覆盖缺口，不能宣称已理解图片、公式和图表。跨教材知识合并、掌握证据自动迁移不在第一版范围。

## 2. 原则

- 知识点组织内容，学习目标定义可观察、可评估的能力。
- 未验证不等于不会，答完不等于掌握，跳过不等于达标。
- 教材模型不受首位学习者水平影响；个性化发生在目标选择与教学过程。
- LLM 提供结构化建议；Python 校验依据、控制状态并执行写入。
- 原始回答不可覆盖，评估可以修正，掌握状态可以重算。
- 每次决策记录原因、教材依据、学习证据和规则版本。

## 3. 架构与技术选择

```text
CLI → 应用服务 → 教学策略
                   ↑
        教材知识服务 + 学习者模型
                   ↓
          LLM 网关 + 领域校验
                   ↓
            SQLite / 本地文件
```

| 模块 | 职责 |
|---|---|
| CLI | 命令、终端展示、输入和取消，不包含评分规则 |
| 应用服务 | 协调用例、操作 ID、事务边界和恢复 |
| 教材知识服务 | PDF、章节、原文、目标、依赖、版本和质量校验 |
| 学习者模型 | 学习证据、目标掌握、误解状态、复习 |
| 教学策略 | 选择目标、动作、补救路径与停止条件 |
| LLM 网关 | 知识提取、内容生成、语义评估和严格输出契约 |
| 存储层 | 持久化、迁移、唯一约束和数据目录写锁 |

采用 Python 3.11+、Pydantic、PyMuPDF、SQLite 和 pytest。普通 Python 状态机协调模型调用，第一版不依赖 Agent 框架。具体模型 SDK 在实现时验证后选定，供应商适配封装在网关内。

## 4. 教材导入与版本

1. 校验文件类型、大小、可读性，计算内容哈希。
2. 逐页提取，优先保留书签目录；启发式目录附置信度。
3. 建立原文片段，记录 PDF 物理页码（从 1 开始）及页内文本范围；印刷页码仅为可选展示信息。
4. 分批提取知识点、目标、评分要点、必要前置依赖，合并去重。
5. 检查引用、目标重复、悬空依赖和依赖环。
6. CLI 展示覆盖范围、疑点和待确认项，用户确认后发布不可变知识版本。无证据目标和未解决的必要依赖阻止发布。

教材提取不接收学习者水平。缓存键包含文档哈希、解析版本、提取提示词版本、模型标识和契约版本。失败草稿不作为可教学版本。

长章节分段处理，不静默截取前段。教学时按目标检索片段，并在上下文预算内保留原文页码。证据不足则拆分目标或报告缺口，不以整个章节范围替代无效引用。

知识点稳定身份与内容版本分离。改名不改变身份；语义变化创建版本或新 ID。重提取产生草稿，不覆盖已发布内容。拆分、合并保留映射，但第一版不自动继承旧掌握结论。会话始终绑定知识版本。

## 5. CLI 契约

以下命令均待实现：

```text
teach import <path.pdf>
teach books
teach outline <book-id>
teach inspect <version-id>
teach publish <version-id>
teach start <book-id> --section <section-id>
teach start <book-id> --point <point-id>
teach resume [session-id]
teach progress [book-id]
teach review [book-id]
teach reassess <attempt-id> --reason <text>
```

start/resume 进入交互。普通文本作为回答；多行输入以 `/answer` 开始、单独一行 `/end` 提交。`/` 开头保留为命令。

| 会话命令 | 行为 |
|---|---|
| `/hint` | 逐级显示提示并记录事件 |
| `/continue` | 在反馈阶段确认继续，空行或“继续”等价 |
| `/explain` | 请求讲解；涉及题目答案时标记答案暴露 |
| `/skip` | 跳过当前目标，不更新为掌握，检查后续依赖阻塞 |
| `/progress` | 展示证据、掌握、缺口与复习 |
| `/why` | 展示当前决策依据 |
| `/pause`、`/quit` | 保存检查点后退出 |
| `/help` | 命令帮助 |

Ctrl+C 暂停，EOF 保存后退出。模型生成未提交时中断，不推进教学状态。恢复时复用已保存的题目和评估，不重新生成。参考答案和 rubric 在提交前不展示；展示答案后的重复回答不算独立掌握证据。

## 6. 配置与数据

新数据默认使用 `data-v2/`，不得自动读取或迁移旧 `data/learning_agent.db`。SQLite 保存版本、题目、原始回答、评估修订、掌握投影、决策和会话事件，本地文件保存 PDF。

实现时重新建立项目依赖与配置模板。配置包括数据目录、模型、服务地址、密钥、超时、上下文与输出预算、重试及日志等级。浏览本地教材和进度无需模型密钥；需模型的命令执行前检查配置。新配置统一使用 TEACH_ 前缀，旧 `.env` 不自动加载，只有显式 `--env-file` 才读取指定文件。

明确提示教材片段和回答可能发送给配置的模型服务。常规日志仅记录操作 ID、阶段、耗时、用量和错误类型，不记录密钥、教材正文、原始回答或完整提示词。
