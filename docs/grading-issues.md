# 评分与学习进度问题讨论记录

记录日期：2026-10-21。

本文记录实际使用中发现的问题、已有改动和后续讨论方向，不代表后续方案已经实现或全部确定。本次仅补充记录并提交已有改动，不开发新功能，不修改历史作答或评分。

## 1. 当前问题与代表案例

### 评分偏重表达形式，未充分识别语义证据

- 学习者回答 `report_id: "007" 不能用数字7, format: "pdf" 需要改成小写，枚举值是小写的pdf`，已给出正确字段、取值和约束依据，却因未写成完整 JSON 对象、未重复前导零及 description 的局限等说明，被评为 67.5 分。该题没有明确考查严格 JSON 语法，部分额外解释还是题干已给前提。之后人工发起模型复核，最新评分为 100 分。
- 另一题已说明新配置由开发者提交、具体调用在模型响应中生成，学习者回答“新配置是tools,响应的具体调用是tool_calls”。模型未充分考虑这些名称的上下文指代，因未再次复述来源扣分，整题得 75 分。
- 同一题中“符合参数约束……只是参数的值不正确”的补充评价缺乏题内依据，但评分记录明确未因此扣分，应与第一问的争议区分。

这里的问题并不意味着所有简短回答都应通过：若缺少题目明确要求的核心推理，或表达存在实质歧义，仍需要补充证据。

### 刚性通过规则放大评分偏差

模型对每个评分项只返回 `0 / 0.5 / 1`，程序要求加权总分至少 0.8 且所有关键项满分。`critical` 当前默认值为 `True`。若模型将补充说明也列为关键项，或把等价表达误判为部分正确，细小表达差异就可能使整题未达标。

### 达标计数清零容易造成进度丢失的感受

当前 `independent_passes` 表示最近一次有效独立失败之后，不同场景的独立达标次数，并非历史累计通过次数。一次新的独立失败会清空本轮计数。因此此前为 `1/2`，随后一次未达标可能变成 `0/2`；历史通过记录仍然存在，并未删除。

此行为来自现行规则，不是数据库丢失作答。是否更改规则尚未决定。

### 提示维护和验证方式不足

记录时评分提示仍嵌入 Python 代码，针对实际误判不断追加规则和具体例子。2026-10-22 已将提示文本迁移到包内文件，保持发送内容不变。仅增加提示长度或独立管理文件不能证明模型会在其他题目上稳定、公平评分。现有自动化测试主要验证结构、状态和数据一致性，不等于真实模型语义评分质量评估。

## 2. 已完成的改动及其边界

- 教学及进度页显示已有知识点标题、学习目标和中文状态，反馈读取最新掌握状态；编号作为辅助信息。
- 展示本题得分、未满分项及原因、独立达标差距、辅助作答和关键误解说明。
- 进度补充已作答、待复核、无效题及待评分数量，并提供历史待复核记录的复核命令。
- 移除程序将“总分达到 0.8 但关键项未满分”的有效评分强制改为 `needs_review` 的行为；此类结果保留为有效未达标证据。模型自身返回的待复核结果仍不计入掌握。
- 提示增加接受等价表达、理解唯一上下文指代、禁止隐含扣分、避免评分项捆绑额外解释等要求。

这些改动未取消数值评分、关键项满分门槛或独立失败清零规则，也未实现局部追问。旧评分不自动重写；显式复核通过新增修订更新投影，不覆盖原记录。提示调整尚缺系统性的真实模型回归验证，不能宣称已彻底解决误判。

## 3. 后续讨论方向：尚未实现

### 提示词独立管理与真实模型评估集

建议将通用提示与各操作提示独立到包内文件，代码负责读取、组装及附加 JSON Schema，记录提示版本或内容哈希。先保持行为不变地迁移，再依据评估结果修改通用规则。

2026-10-22 进展：提示文件独立化已完成，并增加迁移前消息基线对比测试；提示版本或哈希持久化及真实模型评估集尚未实现。维护方式见 [后端文档](backends.md#6-提示词维护)。

实际误判案例应进入评估集，同时覆盖简短正确、等价表达、上下文指代、真实知识错误、缺失核心推理、严格格式要求和题干与评分项冲突。修改提示后需用真实后端验证误扣分与错误放行，而不只检查程序测试通过。

### 用能力证据形成题目结论

讨论中的方向是让模型依据学习目标及回答证据，返回“本题通过、需要补充、需要补练、无法评价”，并说明已证明的能力、缺失点和回答原句。数值分数可以取消或仅作辅助，具体取舍尚未确定。

本题结论与目标掌握分开：模型负责解释本次证据，程序负责校验、保存，并综合独立性、不同场景、提示和误解等证据决定目标状态。仅将加权分数替换成模型布尔值不能保证公平，出题质量和评估集仍必需。

### 局部追问流程

讨论的建议流程：

```text
提交整题 → 评价能力证据
  ├─ 已证明核心能力 → 本题通过
  ├─ 明确知识错误 → 针对性讲解和补练
  ├─ 基本正确但证据不明确 → 聚焦缺失点追问 → 合并原回答和补充回答再判断
  └─ 题目或评分依据有问题 → 无法评价，不计学习者失败
```

- 原回答已经足够明确时直接通过，不为走流程强行追问。
- 仅补问原题要求范围内的缺失点，保留已答对部分；建议每题最多两轮，每轮一个问题。
- 追问期间不显示待确认部分的答案，不新增失败次数，也不改变已有达标计数。
- 原回答和补充回答构成同一次作答，整题最终只计一次；中性追问未泄露答案且未使用提示时可作为独立证据，提供提示或讲解后按辅助练习处理。
- 达到追问上限仍不能确认时，应明确剩余缺口；证据不足与明确答错要区分，不能机械推断未掌握。
- 未来需增加等待补充回答的会话阶段、缺失点与追问记录，支持暂停恢复；交互继续使用文字输入和 `/end`。

上述为流程讨论，不是当前可调用功能，最终接口及结论边界仍需实现前确定。

## 4. 尚待决定的计数规则

已讨论两个选项，尚未收到最终选择：

1. 保留累计独立达标次数；出现新失误时标记待补练，独立补练达标后再判断掌握。这是当前建议方向。
2. 保留现有失败清零规则，同时展示历史累计通过和本轮达标次数，避免让用户误以为历史记录被删除。

此前明确保留的单题与掌握标准仍有效，不能把讨论建议当作修改授权。历史复核可能改变最新有效证据，届时计数也应随证据重放变化。

## 5. 建议推进顺序

先完成提示文件独立化和真实模型评估集，再实施能力判断与局部追问；计数规则另行确定。分开验证各项改动，避免同时更改提示、通过标准与计数方式后无法判断效果来源。
