# 实施与验收

状态：已完成可运行 CLI 原型，验证范围及尚待验收项见[原型说明](prototype.md)。下文保留完整实现与验收目标，无旧接口和数据库兼容要求。

## 1. 建议目录

```text
src/teaching_agent/
  cli.py
  application/   # 导入、教学、恢复、复习用例
  domain/        # 契约、规则、状态机、规划
  knowledge/     # PDF、片段、抽取、版本发布
  learner/       # 掌握、误解、复习
  llm/           # 网关、提示词与输出模型
  storage/       # SQLite、迁移、本地文件
tests/
  fixtures/
  unit/
  integration/
  evaluation/
```

这是规划，不预先创建空实现。领域层不依赖终端、具体模型 SDK 或数据库连接。七个模块的接口和处理细节见[模块设计索引](modules/README.md)，实现时按该契约建立代码，而不是根据目录名各自猜测边界。

## 2. 实施顺序

| 阶段 | 交付与验收 |
|---|---|
| A 领域规则 | 契约、状态机、掌握更新、决策记录，以固定回答覆盖正确、错误、提示、歧义和跳过 |
| B 教材建模 | 逐页解析、片段、目标、依赖校验和发布，目标可回到原文，循环与无依据内容不可发布 |
| C 模型和存储 | 严格契约、SQLite、幂等、修订重算，非法输出不污染状态，中断可恢复 |
| D CLI 闭环 | 导入、开始、提示、作答、暂停、恢复、进度，三类学习者路径不同 |
| E 复习与质量 | 到期队列、新场景验证、固定评估集与版本化报告 |

实现时重新建立 pyproject 和配置模板，依赖实际验证后锁定。默认测试使用离线假网关；真实模型测试显式启用，避免默认产生费用。

## 3. 事务与恢复

领域对象分表，学习目标、题目、原始作答和评估修订独立保存。掌握状态是可重建投影。

约束包括文档哈希唯一、作答操作 ID 唯一、作答内评估修订号唯一、会话事件序号唯一、每会话最多一道活动题。同目标可以多次教学，不设置同会话同知识点只能教一次的限制。

模型调用不持有写事务：

1. 短事务保存待处理操作、原始输入和会话预期修订号。
2. 调用模型，执行契约和领域校验。
3. 短事务检查修订号，一次提交评估、掌握、复习、事件和检查点。
4. 冲突不覆盖新状态，明确提示重试或复用已提交结果。

操作记录类型、输入引用、状态、时间和错误。恢复时复用已提交结果；相同操作 ID、不同输入必须拒绝。进程中断可恢复待处理评分，不重复计分。

导入先写临时文件，验证后发布；失败草稿不可教学。数据库包含 schema 版本，未知版本拒绝写入；迁移使用编号与备份。新数据默认 `data-v2/`，不自动读取旧数据。

## 4. 模型与资源限制

- 提取、生成、评估分别设置输入输出契约及提示词版本。
- 教材和回答都是不可信数据，其中的命令不得改变系统指令或评分规则；不执行模型生成代码。
- 验证字段、目标归属、引用、证据摘录和评分一致性，不用 JSON 可解析替代领域验证。
- 按目标选取片段，明确上下文预算，不静默丢弃教材后段。
- 初始请求超时 90 秒；格式修复最多 1 次，网络或限流最多额外重试 2 次。
- 每逻辑操作最多 4 次网关请求、总墙钟预算 180 秒（含退避），任一上限达到即停止。SDK 自动重试关闭或计入同一预算。
- 作答独立复核共享评分操作的请求预算；教材按批创建操作，每批独立预算，导入整体显示累计用量。操作在恢复时不重置预算，新的显式重试关联原操作且不重复计分。
- 第一版同一数据目录只允许一个写进程，由操作系统排他锁保护；只读命令可查询已提交快照。写进程每次最多一个模型请求，不实现租约、心跳和多进程投影冲突处理。
- 日志记录 ID、阶段、耗时、错误和 token 用量，不记录密钥和正文。
- 取消与超时保留最后已提交状态；重试不保证供应商侧只计费一次。

## 5. 验收矩阵

| 场景 | 必须满足 |
|---|---|
| 已掌握基础 | 减少重复讲解，记录依据 |
| 只会定义 | 不提高应用目标，安排针对性教学 |
| 缺前置知识 | 诊断、补救、独立验证后返回原目标 |
| 所有题答错 | 不因答完而宣称掌握 |
| 提示后答对 | 辅助证据，继续独立新题验证 |
| 看过答案后复述 | 不增加独立掌握证据 |
| 正确但措辞不同 | 按含义与要点评估 |
| 歧义题或缺证据 | 不扣掌握，换题或报告缺口 |
| 跳过必要前置 | 后续目标阻塞并报告缺口 |
| 误解已被新题纠正 | 转 resolved，不作为当前误解继续注入 |
| 历史证据过期 | 复测，不直接判不会 |
| 教材重提取 | 旧会话仍绑定旧版本，历史可追溯 |
| 非法目标、分数或引用 | 拒绝状态更新 |
| 重复提交 | 一次有效提交，其余复用或冲突 |
| 第二写进程启动 | 写锁拒绝，已运行会话不受影响；只读查询可继续 |
| 写进程崩溃 | 操作系统释放锁，新进程可恢复遗留操作 |
| 评分中断 | 保留原始作答，恢复后不重复计分 |
| 反馈展示前中断 | 恢复已保存反馈，不重新评分 |
| 修正历史评分 | 保留旧修订，重算结果与有效证据一致 |
| 首次独立失败后两次独立 0.8 且关键项完整 | 第二次通过后达标，趋势分数低于 0.8 不阻塞 |
| 首次独立通过但尚未达到两次 | 下一步为另一新颖性组的新题验证 |
| 连续 ADVANCE | 自动到下一可交互任务或总结，不停在 planning 等待输入 |
| 内部规划状态不变 | 返回 POLICY_STALLED 并暂停，不持续循环 |
| 第 8 次作答形成达标证据 | 正常达标，不被总作答预算拒绝 |
| 第 8 次作答后仍无独立证据 | deferred，允许讲解/跳过/结束，不再出题 |
| 普通题通过与有针对性反驳 | 普通通过不解除误解；两道新场景独立通过且 refutes 才解除 |
| valid 修订成 invalid_question 或 needs_review | 移除旧分数、通过和误解影响，重算复习及未结束会话缓存 |
| 修订事务中途失败 | current 指针和所有投影整体保持旧版本 |
| 恶意教材或回答 | 不执行代码、不泄密、不更改规则 |

## 6. 验证与发布门槛

单元测试覆盖规则、状态与重算；集成测试使用临时 SQLite、自建可分发 PDF 与假模型，覆盖中断恢复、事务和幂等；CLI 测试覆盖中文路径、多行输入、Ctrl+C 和 EOF。

建立至少 3 个知识点，分别含概念、原理和应用目标；准备至少 30 条人工标注回答，覆盖正确、部分正确、措辞差异、误解和歧义。建立三类学习者路径剧本以及教学中未出现的新场景题。

发布门槛：确定性验收全部通过；固定集的通过/未通过判断与人工一致率至少 90%；所有展示引用可追溯，人工抽查支持对应结论；固定集中的歧义题和无效引用不得更新掌握。保存模型、提示词和规则版本，变更后与基线比较。

工程验收不等于学习效果已经得到证明。真实试学分别记录前测、独立后测、延迟复测和耗时，不把同一题重复作答当作能力提升证据。
