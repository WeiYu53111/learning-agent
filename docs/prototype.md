## 1. 先审核章节，再开始教学

流程：本地导入 → 选择章节或页范围 → 生成草稿 → 程序校验 → 模型审核 → 最多两轮自动修订及复审 → 确认学习范围 → 发布 → 教学。

`draft` 默认执行完整准备流程，`--extract-only` 仅提取。已有草稿用 `prepare VERSION`；该命令及 `draft --resume VERSION` 从已保存阶段继续，修订后复审失败不重复修订。普通恢复不重置轮数，`prepare VERSION --retry` 显式开启新任务。所有意见均尝试修复，两轮后仅剩 warning 可以确认，仍有程序错误或 error 则暂停。进度覆盖提取、审核、修订、复审及保存，长调用每 15 秒报告当前阶段和耗时。准备完成后交互终端当场询问是否开始；非交互执行不发布，稍后可用 `start VERSION` 确认。

草稿包含知识点、可考核目标、先修关系、原文引用、代表题、参考答案、评分要点，以及原文内容清单。清单将定义、机制、步骤、边界和例子映射到目标，或记录排除理由。自动审核双向检查每个目标是否有依据、重要原文内容是否都有对应目标。学习者确认范围及剩余提示，不承担专业校对。

程序检查引用是否真实且唯一、关联目标是否存在、先修关系是否有环、排除目标是否仍被依赖、目标是否关联内容清单、所有文本片段是否有清单记录。片段覆盖数不能证明语义完整或粒度适当。模型审核用于发现遗漏、重复和顺序问题，审核通过不保证内容绝对正确；开始学习仍需用户接受。

`teach inspect VERSION` 展示清单、代表题和拓扑排序后的教学顺序。`teach source VERSION [CHUNK]` 对照原文。`teach review VERSION` 进入交互审核：

| 命令 | 用途 |
| --- | --- |
| `show` | 重看清单及审核结果 |
| `source [CHUNK]` | 查看原文 |
| `edit OBJECTIVE 描述` | 修改目标描述 |
| `pre OBJECTIVE 前置1,前置2` | 修改先修关系；用 `-` 清空 |
| `exclude OBJECTIVE 理由` | 排除目标；依赖它的目标需同时调整 |
| `audit` | 重新执行模型审核 |
| `resolve 编号 理由` | 记录模型问题的人工处理意见 |
| `approve` | 确认当前修订 |
| `publish` | 发布已确认的修订 |
| `quit` | 保留已有修改并离开 |

复杂拆分、合并、补充目标可导出编辑：

```text
teach export VERSION chapter.json
# 修改 points/objectives/content_items 以及关联 key
teach apply VERSION chapter.json
teach audit VERSION
teach review VERSION
```

也可运行 `teach revise VERSION --instruction "拆分变量绑定与共享引用，补齐代表题和原文映射"` 后人工核对。真实模型命令需在子命令前指定 `--env-file .env`，或预先设置环境变量。离线演示不模拟自然语言校正。

任何修改都会清除旧准备状态、审核、问题处理意见和确认，必须重新准备或审核。模型报告的 error 必须经修订和再审核消除，人工备注不能放行；程序结构错误不能用人工说明绕过。发布版本不可修改，使用 `teach clone VERSION` 创建新草稿。新版本不自动继承旧掌握状态。

## 2. 教学和证据

`teach progress VERSION` 与教学中的 `/progress` 按已保存的知识点标题和具体目标描述分组展示，编号作为辅助信息。顶部按目标汇总已掌握、待复习、学习中、待补练、未验证数量；排除项展示原因但不计入总数。各目标保留独立通过次数、趋势分和有值的复习时间，关键误解显示中文描述及编号。“未验证”表示尚无有效评分证据，不保证从未作答；已练习也不等于已掌握。教材排列顺序不表示实际下一题顺序。

`teach start VERSION` 按先修顺序学习；`--point POINT` 选择知识点及必要前置；`--due` 只选择到期复习目标。`--no-chat` 只生成当前任务，便于脚本操作。

默认回车换行，单独输入 `/end` 提交当前小问；多小问依次回答，全部完成后统一评分，仍算一次作答。反馈后回车或 `/continue`。`/cancel` 清空当前输入而保留已提交小问，`/answer` 为兼容提示入口。支持 `/hint`、`/explain`、`/skip`、`/why`、`/progress`、`/pause`。完整输入行及小问进度随会话保存，暂停、EOF、Ctrl+C 后可恢复。普通答案若以斜杠开头，可用 `//` 转义。

最后一问或 `answer --text` 的回答落库后显示“回答已保存，正在评分，请稍候。”，等待期间每 15 秒更新耗时，评分校验并保存后显示“评分完成。”。恢复待完成评分时显示相同提示，沿用原作答记录。前面的小问只显示保存提示。

出题引用须逐字匹配本次提供的原文且在对应片段内唯一。无效候选及具体错误记入 `task_rejected` 事件，并反馈给模型自动修正一次；修正后仍执行目标、动作、误解及题目重复校验。仍失败时不推进会话或增加作答，可 `/continue` 重新生成；重试不会复用事件中的失败候选。出题和修正期间均显示等待进度。

最近一次独立失败之后，取得两道不同题组的独立达标证据，且无已确认的关键误解，才算掌握。单题要求加权分至少 0.8、所有关键要点满分。趋势分仅作展示。提示后的作答以 0.7 系数计入趋势，不构成独立通过。请求讲解会撤销当前题目，之后使用新题。

教学视图在出题、反馈和恢复时关联已保存的知识点标题及目标描述，显示最新掌握投影；出题时的历史决策留在 `/why`。有效评分展示百分制总分、达标与否及未满分项原因，反馈时才展示评分要点。高分但关键项未满分不再被程序改成待复核，而是保留有效未达标结果。真正的待复核或无效题不计入掌握证据，进度附作答及异常评分数量。旧评分原样保留，复核按每次作答最新修订重放进度，不自动调用模型修复历史记录。

所有展示过的题目均留历史，包括未回答的题目。同题面或同题组不能再次作为新题下发。程序只能核对题面和模型标注的题组，不能保证语义上真正独立。

首次掌握一天后复习，后续通过按 3、7、14 天安排；失败后重新补救。跳过前置会阻塞依赖目标。目标达到预算（8 次作答、3 次有效失败、2 次无效题或连续 2 次待复核）后暂缓，会话可能以 `ended_with_gaps` 结束，不会将其算作掌握。

`teach sessions` 查询会话，`teach resume SESSION` 恢复。作答先保存再评分，评分失败可恢复，不重复创建作答；题目、提示次数和阶段一起保存。

```text
teach progress VERSION
teach answer SESSION --text "答案"
teach next SESSION
teach attempts SESSION
teach reassess ATTEMPT --reason "原评分误解了回答，重新复核"
```

重新评分新增修订，不覆盖原始作答及旧评分；进度按最新评分重放计算。未结束会话标记为需要重新规划，恢复时撤销不再适用的当前题目。`reassess` 是模型复核，尚无人工评分编辑器或自动双模型仲裁。

## 3. PDF 和模型接口边界

支持文本 PDF，最大 20 MiB、2000 页；拒绝加密、损坏和完全无文本的文件。无文本页会列出页码并排除出教学范围。图表、公式和多栏排版需要人工核对，尚未实现 OCR 和版面理解。

章节优先读取一级书签，其次识别页首章标题，最后回退到全文。按物理页划分，同页章节合并，尚无字符级章节边界。`draft BOOK --section s1 --pages 1:5` 可缩小范围，克隆保留该范围。

提取分批保存检查点，失败后用 `draft --resume VERSION` 恢复。各批 key 加前缀合并，跨批重复、先修关系与整体顺序需要章级审核校正。

结构化提取结果若未通过原文引用或覆盖等业务检查，会保存为 `batch_rejected` 事件，并携带具体错误调用一次 `revise` 校正；仍失败则停止。恢复时优先校正已保存候选，不重复提取该批。只有重新校验通过后才写入成功批次。每批每次执行最多一次业务校正调用，它独立于各后端自身的传输重试预算。旧版本未保存的失败候选无法找回，首次恢复仍需重新提取。

HTTP 模型网关使用 `/chat/completions`，要求符合 JSON Schema 的完整 JSON，拒绝额外字段、重复 JSON key 和非有限数值，业务层检查原文引用。单次操作最多 4 次 HTTP 请求，包括最多 2 次网络重试、1 次格式修复，并受时限约束。显式恢复开启新的请求预算。Codex 后端通过子进程传递相同教学任务，使用已有登录；其配置、超时和代理行为见[后端说明](backends.md)。

环境变量见 `.env.example`。默认单请求超时 90 秒、操作时限 180 秒、输出上限 8000 token、输入上限 48000 字符。超过输入上限时直接报错，不静默截断。章级审核和自然语言校正仍需完整范围的草稿和原文，长章节建议使用较小页范围。不同模型服务的参数及结构化输出支持需实际联调。

## 4. 存储与设计取舍

- 默认 `data-v2/learning.db`，首次写入建库，教材副本保存在数据目录内，不迁移旧库。
- 每个数据目录一个写进程，使用操作系统文件锁。交互期间保持锁，进程退出释放；只读查询可并行。
- 教材、版本、提取批次、会话、作答、评分修订、事件分别持久化。复杂对象暂存为经校验的 JSON，未展开目标设计中的全部关系表。
- 掌握状态从最新评分重放计算，未使用持久化投影缓存。发布版本和评分记录有数据库约束防止覆盖。
- 模型调用不占用长数据库事务。作答与待评分状态、评分与反馈状态分别原子提交。会话修订号防止过期状态覆盖。
- 尚未实现完整遥测、全量模型调用审计、跨进程持久化重试预算和备份工具。

## 5. 验证情况

当前完整回归为 45 项自动测试通过，Ruff 检查通过；包含后端配置、迁移、代理、Codex 调用，以及引用校正和失败候选恢复测试。

自动测试覆盖审核发布、引用与先修关系、失败恢复、连续独立通过、提示降权、复习、误解证据、评分修订失效、单写锁、模拟 HTTP 契约，以及真实 CLI 子进程中六次作答的完整教学闭环。

离线演示只用固定三页教材和关键词评分，每个目标三个场景，用于验证流程。在线后端的传输验证与教学质量验收分开记录。知识划分是否充分、粒度是否合理、出题和评分是否可靠，仍需选择实际教材一章，人工审核清单、顺序和代表题，再用正确、部分正确、误解及偏题答案验收后扩大范围。

## 6. 当前命令清单

以下命令均以 `teach` 开头。`BOOK` 为教材 ID，`VERSION` 为草稿或发布版本 ID，`SESSION` 为会话 ID，`ATTEMPT` 为作答 ID。全局参数 `--env-file PATH`、`--data-dir PATH`、`--config PATH`、`--backend NAME` 放在子命令之前。

| 命令 | 作用 |
| --- | --- |
| `demo` | 创建离线演示教材、草稿并执行演示审核，等待人工确认 |
| `import PATH` | 本地导入 PDF，不调用模型 |
| `books` | 列出教材 |
| `outline BOOK` | 查看章节 ID 和物理页范围 |
| `draft BOOK --section SECTION [--pages START:END]` | 自动提取、审核修订和复审；默认章节为 `s1`，--extract-only 仅提取 |
| `prepare VERSION [--retry]` | 准备已有草稿或恢复任务；--retry 显式开启新任务 |
| `draft --resume VERSION` | 继续尚未完成的分批提取 |
| `drafts` | 按创建时间从新到旧展示教材文件名、章节标题、PDF 页范围、中文状态、审核待处理数量、版本 ID 和下一步命令；包括已发布版本 |
| `inspect VERSION` | 查看知识清单、顺序、代表题及审核状态 |
| `source VERSION [CHUNK]` | 查看范围内全部文本或指定片段 |
| `review VERSION` | 进入人工交互审核 |
| `audit VERSION` | 对当前草稿执行结构检查与模型审核 |
| `resolve VERSION INDEX --note "理由"` | 记录审核问题处理意见；编号从 1 开始 |
| `approve VERSION` | 人工确认当前修订 |
| `publish VERSION` | 发布已确认修订 |
| `clone VERSION` | 基于已有内容创建新草稿 |
| `delete VERSION` | 永久删除未发布草稿及关联提取批次、事件和后端绑定；保留教材，拒绝删除已发布版本 |
| `delete-book BOOK` | 永久删除无关联版本的教材及数据目录内 PDF 副本；保留原始导入文件 |
| `delete-book BOOK --cascade` | 永久清除该教材全部数据，包含已发布版本、会话、作答、评分、知识结构及问答；保留原始 PDF 和其他教材 |
| `export VERSION FILE` | 导出草稿 JSON；不覆盖已有文件 |
| `apply VERSION FILE` | 将编辑后的 JSON 应用到草稿 |
| `revise VERSION --instruction "要求"` | 输入完整草稿和原文，返回局部修改包；程序合并后完整校验 |
| `start VERSION [--point POINT] [--due] [--no-chat]` | 开始教学；选择知识点或到期复习时分别使用相应选项 |
| `resume [SESSION] [--no-chat]` | 恢复会话；仅一个未结束会话时可省略 ID |
| `sessions` | 列出会话及阶段 |
| `progress VERSION` | 查看目标掌握、独立通过次数、趋势和复习时间 |
| `answer SESSION --text "答案"` | 提交当前题目答案 |
| `next SESSION` | 在可推进阶段生成下一步任务 |
| `attempts SESSION` | 查看原始作答及最新评分修订状态 |
| `reassess ATTEMPT --reason "理由"` | 对已有评分的作答重新调用模型评估并保存修订 |

审核内命令见第 1 节；教学内命令见第 2 节。`teach --help` 与 `teach 子命令 --help` 可查看实际参数。

## 7. 尚未实现的能力

- 无教材依据时自动切换通用问答。
- 将自由提问保留为学习线索，并在解释后按用户意愿进入诊断的完整流程。
- Web 写操作与学习工作台、OCR、向量检索、多用户并发写入，以及第 4 节列出的存储与运维扩展。本地只读 Web 已支持教材内容、原文与关联知识检查，使用 `teach web`，见 [启动说明](../README.md#web-内容与关联知识检查)。

教材内自由提问 `teach ask` / `/ask` 和跨章节原文检索已经实现，原文导入后即可使用，无需完成全书梳理。无依据时明确说明，不切换通用问答。当前 `/explain` 只针对当前学习目标提供讲解；插问请使用 `/ask 问题`，普通文本仍作为作答。未来工作与验收事项统一见[计划总览](plans/README.md)和[待办清单](plans/backlog.md)。
