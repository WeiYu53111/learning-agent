### 本机个人 Web 交互

讨论日期：2026-10-23。状态：**未排期，仅初步讨论**。以下记录方向与初步技术判断，不是已批准的实施方案。

- 使用方向：先做本机个人版本，通过浏览器交互；个人版本成熟后再考虑多人在线使用。
- 初步判断：现有教学与评分核心、模型后端、SQLite 和检查点可以复用，本机版本可继续使用本机 Codex 登录及配置。但当前程序不能直接套一层 HTTP 接口就满足 Web 交互要求。
- 共用应用层：需评估将 CLI 中的发布确认、前置知识选择等流程抽成共用用例，由 CLI 和 Web 分别展示；倾向直接调用应用服务，而非执行 `teach` 并解析终端输出。
- 后台任务：需评估任务 ID、结构化进度和恢复接口。页面关闭或刷新不应丢失已提交任务，服务重启后可依据检查点恢复。
- 写入与重复请求：需评估统一写入调度、双击或重发去重、多标签页版本冲突。初版倾向保留单写策略，不能假定接入 Web 后即可并发梳理和评分。
- 页面数据：需定义适合交互的题目、当前小问、反馈及可执行动作视图；不能直接返回可能含参考答案和评分标准的内部会话对象。
- 后续多人版：需要另行设计用户归属、权限隔离、模型凭据管理和并发调度；当前不因此引入账户系统、分布式队列或更换数据库。
- 与当前工作关系：稳定性改造可兼顾错误、进度和恢复信息的结构化，作为未来 Web 的基础；此讨论不扩大本轮稳定性计划的实施范围。

技术选型、页面范围、部署方式、接口契约和验收标准均未确定。正式推进前再形成专项计划，本次只保存讨论记录。

推进某项工作时，在本目录建立或更新专项计划，并同步总览状态；本页保留摘要和来源，不复制已确定计划的完整实施细节。
