# 长任务稳定性与失败诊断

最后核对：2026-10-23。状态：**待实施**；方案已确定，尚未修改程序。优先级与后续事项见[计划总览](README.md)。

## 目标与现状

优先解决全书梳理中失败原因不明确、临时故障需要手动恢复、累计耗时与当前进度难以判断的问题。

2026-10-23 检查本地记录时，33 个步骤已保存成功，`s5:extract:2` 在约 7.5 秒后因 Codex 退出码 1 暂停；终端的 4613 秒是整次执行累计耗时。旧程序未保存提供方具体错误，不能据此判断是网络、额度还是服务端故障。

保留现有检查点和串行处理方式，不重新生成已经完成的步骤。本阶段不调整模型、教学规则或知识关系算法。

## 1. 让失败原因可诊断

- 为 Codex 调用增加结构化错误信息：失败阶段、错误分类、退出码、耗时、是否可以重试、安全摘要。
- 区分登录失效、额度耗尽、临时限流、网络故障、服务端故障、超时、配置或模型错误、结果格式错误及未知错误。只有明确证据才分类；退出码 1 本身不代表网络故障。
- 默认只保存安全摘要到现有事件记录，不直接输出 Codex 原始内容。
- 新增全局参数 `--diagnostics`：显式开启后，将失败调用的 stderr 保存到当前数据目录的 `diagnostics/`，按任务和调用编号组织。每次最多保存末尾 64 KiB，过滤凭据和认证头；不保存请求正文、完整环境变量或 stdout。
- 详细日志可能包含教材片段，在帮助中说明。终端只显示日志路径；教材级联删除同时清理其关联诊断日志。
- 历史错误继续兼容显示，明确此前没有保留详细信息，不能补回本次失败的原始原因。

## 2. 对临时故障有限重试

- 仅对明确的网络连接故障、临时限流和服务端临时故障自动重试，最多额外两次，退避分别为 2 秒、5 秒。
- 登录失败、额度耗尽、配置错误、超时及未知错误立即暂停；现有内容校验纠正次数保持独立。
- 同一逻辑调用的执行和退避共享 `timeout_seconds` 预算，不因重试重新获得完整时限；预算不足时暂停。
- 显示重试原因、次数及等待时间；记录每次失败，即使后续成功也保留诊断记录。
- 手动恢复开启新的调用预算，成功检查点始终复用。
- 网络失败没有有效候选结果时，恢复不把空候选和网络错误作为“内容纠正”材料发给模型。

## 3. 提供可读的任务状态与恢复入口

- 新增只读命令 `teach status BOOK`，展示最近一次全书梳理的索引 ID、已保存步骤数、最近成功步骤、最近失败及恢复命令。
- 无梳理记录时提示 `teach index BOOK`；已有完成版本及未完成版本时分别展示，避免混淆。
- 不把数据库中的 `building` 直接显示成“正在运行”；显示“未完成”，因为现有记录不能证明进程仍存活。
- 提取进度显示章节标题、章节序号、章节内批次和物理页码；摘要、关系分析显示各自阶段及可确定的批次数。
- 保留内部步骤 key 便于定位，但不再仅显示 `s5:extract:2`。
- “总耗时”改为“本次执行耗时”，与当前调用耗时分开；使用时分秒展示。不提供未经测量的剩余时间或全任务百分比。
- 暂停时输出可复制的恢复命令，保留适用的数据目录、配置和显式后端参数；不自动添加 `--new`。

## 4. 验证与交付

- 使用模拟子进程验证错误分类、摘要过滤、日志截断、日志默认关闭和级联清理。
- 验证重试次数、退避、总预算、中断退出，以及非临时错误不重试。
- 验证失败后恢复复用成功批次，不重复生成或破坏已有教材数据。
- 验证状态查询不调用模型、不创建数据目录，兼容旧事件缺少诊断字段的情况。
- 更新 README、命令导航和后端说明；运行相关测试及完整回归。
- 分两次提交：先交付诊断与重试，再交付状态查询与进度展示。不自动启动真实教材长任务。

完成后，再用真实教材记录调用次数、耗时与质量，决定下一轮性能优化。
